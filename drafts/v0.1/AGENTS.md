# AGENTS.md — 仅适用于 human-ai-governance 仓库

本文件约束**维护本治理规范仓库的 Codex**。它不自动约束其它项目仓库、ChatGPT 会话或系统全局配置；不授予 CLI、MCP、生产、账号或 GitHub 写入权限。

## 修改本仓库时

1. 先核实际工作目录、本仓库适用的上级及嵌套 `AGENTS.md` / `AGENTS.override.md`；仅加载准确作用域内的规则。
2. 小改只读相关文件；涉及权责/授权/单写/恢复时，读 `GOVERNANCE.md`、`CODEX-PROTOCOL.md`、`HANDOFF.md`。不强制每个小改扫描全仓库或外部项目历史。
3. 维持本仓库与项目事实分离：`projects.yaml` **只维护入口索引与采用状态**，不得复制当前 NEXT、业务 PASS 或真实执行令。
4. 更改长期规则、授权类别或窗口切换流程，先提交可审 diff 和失败场景；需要独立审查和用户批准后才能标记生效。
5. 禁止引入凭据、Cookie、SID、token、生产密钥、真实认证 HTTP 正文、私人浏览器状态或未脱敏日志；不把敏感值及其可还原衍生值写入 Git。
6. 如果工作目录、远端 HEAD、项目权限或已发布版本不清楚，只报告缺口并停受影响写动作，不靠切工具规避。
7. 不顺便修改、创建或迁移 HOT/AUTH/BBS 等项目仓库；对项目的任何治理采用/负责人交接都按其自身权威流程和用户明确授权执行。
8. 完成后报告实际改动文件、commit/文件 hash（若已提交）、测试/审查范围、未覆盖项和停止条件。新规范不能冒称系统级强制锁。

## 审查重点

- 没有把“GitHub 规则存在”误写为“各运行窗口已自动加载”。
- 没有把 `includeTurns=false`、工具退出码 0、合成 PASS 误写为业务验收通过。
- 没有双账本、隐式 writer 转移、旧授权重放、敏感值落盘、跨项目自动派工。
- `GOVERNANCE.md` 的稳定方法与 `projects.yaml` 的项目入口不互相复制动态状态。

## Promotion 及规则生效边界

本文件位于 `drafts/v0.1/` 时仅为审查对象；若按准确白名单合并为治理仓库的**根 AGENTS.md**，即可能在实际工作目录被 Codex 读取，即使还没有发布标签。须先审查最终 root 作用域、用户批准和文件哈希；规则只治理本仓库的维护，不自动授予其他项目的派工、账本写入或运行权限。
